# Методология

Здесь по каждому модулю расписано, что он считает, на каких предпосылках и когда
его стоит применять. Формулы записаны так же, как они реализованы в коде
(`src/abtest/`), поэтому документ можно читать рядом с исходниками. Английские
термины оставлены как есть, греческие буквы - это обычные обозначения из
статистики (alpha, beta и т.д.), всё остальное записано ASCII.

## 1. Планирование: размер выборки, мощность и MDE (`power.py`)

Три понятия, вокруг которых всё крутится:

- alpha (уровень значимости) - вероятность ошибки I рода, то есть вероятность
  отвергнуть верную нулевую гипотезу (поймать эффект там, где его нет).
- beta - вероятность ошибки II рода, а мощность = 1 - beta - вероятность
  обнаружить эффект, если он на самом деле есть.
- MDE (minimum detectable effect) - наименьший эффект, который эксперимент
  способен надёжно поймать при заданных alpha, мощности и размере выборки.

### Доли (конверсии)

Для двух долей беру нормальную аппроксимацию двухвыборочного z-теста. Размер
контрольной группы n1 при соотношении групп k = n2/n1:

```
n1 = ( z_{1-alpha/s} * sqrt(p_bar(1-p_bar)(1 + 1/k))
       + z_{1-beta} * sqrt(p1(1-p1) + p2(1-p2)/k) )^2 / (p1 - p2)^2
```

где p_bar = (p1 + k*p2)/(1 + k) - пулированная доля под H0, s это 1 или 2
(одно- или двусторонняя). Первый корень берёт дисперсию под нулём (пул), второй -
под альтернативой (раздельную). Это стандартная формула (Chow, Shao & Wang).

Мощность при известных n1, n2 считается обращением той же логики:

```
power = Phi( (|p2-p1| - z_{1-alpha/s} * SE0) / SE1 )
        + Phi( (-|p2-p1| - z_{1-alpha/s} * SE0) / SE1 )
SE0 = sqrt(p_bar(1-p_bar)(1/n1 + 1/n2))
SE1 = sqrt(p1(1-p1)/n1 + p2(1-p2)/n2)
```

Второе слагаемое - это противоположный хвост, на практике им можно пренебречь.

### Средние (непрерывные метрики)

Тут расчёт точный, через нецентральное t-распределение. Для эффекта d = delta/sigma
параметр нецентральности:

```
ncp = delta / (sigma * sqrt(1/n1 + 1/n2)),   df = n1 + n2 - 2
power = P(T' > t_крит)  [+ P(T' < -t_крит) для двусторонней],  T' ~ nct(df, ncp)
```

Размер выборки ищется численно (метод Брента) как корень уравнения
power(n) = target. Результат совпадает со `statsmodels.TTestIndPower` до 4-го
знака (см. `tests/test_power.py`) - это и есть проверка, что всё посчитано верно.

### Когда что

Доли - для бинарных исходов (клик, покупка, регистрация). Средние - для
непрерывных метрик (выручка на пользователя, время на сайте). У метрик с
тяжёлыми хвостами t-тест всё равно устойчив на больших выборках (работает ЦПТ),
но полезно дополнительно смотреть непараметрику и бутстрап (см. раздел 3).

## 2. Проверка дизайна (`srm.py`)

### SRM (Sample Ratio Mismatch)

Если реальное соотношение размеров групп заметно отличается от запланированного
(например, от 50/50), это признак сломанного сплитования: баг в рандомизации,
потеря событий, фильтрация ботов, редиректы. Даже небольшой, но систематический
перекос делает выводы недоверенными.

Проверяю критерием хи-квадрат согласия:

```
chi^2 = sum( (O_i - E_i)^2 / E_i ),   df = k - 1
```

где O_i - наблюдаемые размеры групп, E_i - ожидаемые по плановым долям. Порог по
p-value тут жёсткий (0.001), а не 0.05: при большом трафике не хочется ложных
тревог, но реальные поломки ловить обязательно. Если SRM найден - это блокер,
анализировать метрики дальше бессмысленно, пока не починишь причину.

### Баланс ковариат

До-экспериментные признаки должны быть распределены между группами одинаково,
иначе к рандомизации есть вопросы. Для числовых признаков считаю
стандартизированную разность средних (SMD):

```
SMD = (x_bar_t - x_bar_c) / s_pooled
```

Признак считаю сбалансированным при |SMD| < 0.1 (общепринятый порог). Для
категориальных - критерий хи-квадрат независимости и Cramer's V как размер
эффекта.

## 3. Анализ результатов (`tests.py`)

### Доли: two-proportion z-test

Статистика теста использует пулированную дисперсию под H0:

```
z = (p_hat_t - p_hat_c) / sqrt(p_hat(1-p_hat)(1/n_c + 1/n_t))
```

Совпадает со `statsmodels.proportions_ztest`. Доверительный интервал на
абсолютную разницу строю по раздельной (Wald) дисперсии. Относительный lift и его
интервал - через дельта-метод для log(p_t/p_c) (так устойчивее, чем Wald прямо на
отношении), потом беру экспоненту от границ.

### Средние: тест Уэлча

Тест Уэлча не предполагает, что дисперсии групп равны (в проде они почти всегда
разные), поэтому по умолчанию беру его, а не классический t-тест Стьюдента.
Степени свободы - по формуле Уэлча-Саттертуэйта. Совпадает со
`scipy.ttest_ind(equal_var=False)`.

### Бутстрап

Непараметрическая оценка интервала для разности средних через ресемплинг.
Реализованы два варианта:

- percentile - просто квантили бутстрап-распределения;
- BCa (bias-corrected and accelerated) - с поправкой на смещение (z0) и ускорение
  (a, через jackknife). BCa точнее при асимметрии, поэтому стоит по умолчанию.

### Манна-Уитни (непараметрика)

Ранговый критерий на случай, когда распределение далеко от нормального или есть
выбросы. Он проверяет стохастическое доминирование, а не равенство средних.
Размер эффекта - rank-biserial correlation: r = 2U/(n1*n2) - 1.

## 4. CUPED: снижение дисперсии (`cuped.py`)

CUPED (Controlled-experiment Using Pre-Experiment Data; Deng, Xu, Kohavi &
Walker, 2013) берёт ковариату X, измеренную до эксперимента (а значит, не
зависящую от воздействия), и вычитает предсказуемую часть дисперсии:

```
Y_cuped = Y - theta*(X - X_bar),   theta = cov(Y, X) / var(X)
```

Так как X не зависит от группы, среднее Y_cuped не смещается - оценка эффекта
остаётся честной. А дисперсия падает:

```
Var(Y_cuped) = Var(Y) * (1 - rho^2)
```

где rho - корреляция Y и X. Снижение дисперсии на rho^2 напрямую повышает
мощность без увеличения выборки - это один из самых практичных приёмов в
индустрии (типичная ковариата - та же метрика за пред-период). theta и X_bar
оцениваю на объединённых данных обеих групп. Симуляция это подтверждает: при
rho = 0.7 наблюдаемое снижение дисперсии около 49% = rho^2.

## 5. Множественные сравнения (`multiple.py`)

Чем больше метрик или вариантов проверяем, тем выше шанс случайной находки. Два
способа держать это под контролем:

- Bonferroni - контролирует FWER (вероятность хотя бы одной ошибки I рода): порог
  делится на число тестов m. Строго, но консервативно.
- Benjamini-Hochberg - контролирует FDR (ожидаемую долю ложных среди отвергнутых).
  Мощнее Bonferroni, это стандарт, когда метрик много.

Обе процедуры возвращают скорректированные p-values и совпадают со
`statsmodels.multipletests` (проверено в тестах).

## 6. Подглядывание и sequential testing (`sequential.py`)

### Чем опасно наивное подглядывание

Если постоянно смотреть на p-value по мере набора данных и останавливаться на
первом p < alpha, реальная ошибка I рода резко растёт: при 20 проверках она
доходит до ~25% вместо 5% (видно на симуляции). Причина - это множественное
тестирование, только растянутое во времени.

### mSPRT: always-valid p-values

Mixture Sequential Probability Ratio Test (Robbins, 1970; Johari, Pekelis & Walsh,
"Peeking at A/B Tests", 2017). Для оценки эффекта Delta_hat_n ~ N(theta, V_n) и
смешивающего распределения N(0, tau^2) смешанное отношение правдоподобия:

```
Lambda_n = sqrt(V_n/(V_n + tau^2)) * exp( Delta_hat_n^2/2 * tau^2/(V_n(V_n + tau^2)) )
```

Lambda_n - это тест-мартингал под H0, поэтому по неравенству Вилля
P(существует n: Lambda_n >= 1/alpha) <= alpha при любом числе проверок.
Anytime-valid p-value: p_n = min(1, 1/max_{k<=n} Lambda_k). Можно смотреть сколько
угодно раз и останавливаться при Lambda_n >= 1/alpha, не раздувая alpha.

### Alpha-spending (Lan-DeMets)

Групповой последовательный дизайн: функция расходования alpha*(t) распределяет
alpha по промежуточным анализам в моменты информации t_k. Реализованы две границы:

- O'Brien-Fleming: alpha*(t) = s*(1 - Phi(z_{1-alpha/s}/sqrt(t))) - рано почти
  ничего не тратит (границы высокие), а к концу работает как обычный тест;
- Pocock: alpha*(t) = alpha*ln(1 + (e-1)*t) - границы примерно постоянны.

Сами границы считаю рекурсией Армитеджа: плотность накопленной статистики
(случайного блуждания в шкале информации) численно протаскиваю между проверками
(свёртка с нормальным приращением через FFT), и на каждой проверке подбираю
границу так, чтобы потратить ровно приращение alpha*. Симуляция подтверждает, что
суммарная ошибка I рода держится на уровне alpha.

### Что когда брать

mSPRT удобен для непрерывного мониторинга (дашборд с живым p-value).
Alpha-spending - для заранее зафиксированного расписания промежуточных анализов
(классика клинических испытаний). Оба корректны; наивный ежедневный z-тест - нет.

## 7. Байесовский анализ (`bayes.py`)

Для конверсии с сопряжённым априори Beta(a0, b0) апостериор после s успехов из n -
это Beta(a0 + s, b0 + n - s). По апостериорам (методом Монте-Карло) считаю:

- P(theta_B > theta_A) - вероятность, что вариант B лучше;
- expected loss - E[max(theta_A - theta_B, 0)] при выборе B (и симметрично для A),
  то есть ожидаемую цену ошибки. Решение раскатывать принимается, когда ожидаемые
  потери меньше порога практической незначимости.

Байесовский взгляд проще объяснить бизнесу ("вероятность, что B лучше, = 97%") и
он естественно работает при мониторинге, не требуя поправок на подглядывание
(правда, чувствителен к выбору априори).

## 8. Интерпретация (`report.py`)

Автоматический вердикт складывает всё перечисленное в одно решение:

1. SRM-блокер - если найден SRM, результат недействителен (это главный приоритет).
2. Статистическая значимость - по (скорректированному) p-value.
3. Практическая значимость - сравнение доверительного интервала эффекта с порогом
   практической значимости: значим ли эффект настолько, чтобы это стоило внедрять,
   и можно ли, наоборот, вообще исключить практически важный эффект.
4. Рекомендация - раскатывать, не раскатывать или собрать больше данных.
5. Предупреждения - недобор мощности, несколько метрик без поправки, эффект в
   нежелательную сторону.

Главная мысль: статистическая значимость это не то же самое, что практическая.
Значимый, но крошечный эффект на огромной выборке - не повод раскатывать, а
незначимый результат при низкой мощности - ещё не доказательство, что эффекта нет.
